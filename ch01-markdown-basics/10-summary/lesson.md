# 10. Summary

You've covered the parts of Markdown you'll use every day. Here are the rules that carry most of the weight.

## The rules

- **Headings.** A `#` for the top level, `##` below it, with a space after the hash signs. Don't skip levels.
- **Paragraphs.** Lines with no blank line between them form one paragraph. A blank line starts a new one.
- **Emphasis.** Two asterisks for bold, one for italics. Inline code uses single backticks.
- **Lists.** A hyphen or a number, then a space, with a blank line before the list. Nest with indentation.
- **Links.** Clear text in square brackets, the address in round brackets, with no space between them. Relative paths for files in the project.
- **Tables.** A header row, a row of hyphens, and one row for each entry, with the same number of columns in every row. A blank line before the table.
- **Block quotes and rules.** A `>` at the start of each line for a block quote. Three hyphens on their own line for a rule.
- **Code blocks.** Three backticks, the language name, the code, and three backticks to close. Use the outer `~~~` fence when the block shows Markdown.

## Before you share a file

Read the source, and then the rendered page. Check the heading levels, the list and table starts, and the links. Confirm the file has no em dashes, which this course's documents avoid. Then share it, as you would share a change to code.
